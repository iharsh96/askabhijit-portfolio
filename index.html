01 / The starting point

Finding one answer should not mean watching hours of video.

I wanted to explore Abhijit Chavda’s views on science, history, and geopolitics, but his answers were spread across hundreds of long YouTube episodes. Finding a discussion on a specific topic meant searching through videos without knowing where the relevant answer was.

My goal was to make those discussions accessible through a question. I built a pipeline that prepares the episode content, retrieves relevant passages, and generates a source-referenced answer. The working prototype brings the answer and its supporting passages into one interface, so readers can explore a topic and check the context.

“What if I could explore the collection through questions—and still see what the answer came from?”

02 / Under the interface

How the application finds and answers a question.

The RAG pipeline has two parts: offline processing prepares and indexes the source collection; at question time, the Flask backend retrieves relevant passages and supplies them to the selected language model as context for its answer. Select a stage below to explore the flow.

Prepare the episode content for search.

The source collection is processed into structured Q&A material for retrieval. Batch APIs handle offline processing, reducing API processing cost by approximately 50% compared with the previous approach.

Episode material↓ offline batch processingStructured Q&A collection↓Retrieval-ready source material

Search by meaning and by keywords.

The application combines a semantic index with keyword retrieval. The two approaches provide complementary ways to find relevant material: conceptual similarity and matching words.

Prepared source material↙           ↘Chroma semantic index + BM25 keyword index↓Two retrieval paths

Find relevant passages for the question.

The Python backend searches for passages using both meaning-based search and keyword matching. Reciprocal rank fusion (RRF) merges the two ranked result lists. The retrieved passages then become context for the language model.

User question → Flask backend↓Semantic search + BM25↓ reciprocal rank fusionRetrieved source passages

Generate an answer with source references.

The selected language model receives the question and retrieved passages. It generates an answer with source references, and the interface lets readers expand the passages to check the context.

Question + retrieved context↓ model generationResponse + source references↓Interactive reading interface

03 / Quality & trade-offs

Testing answer quality and managing cost.

I tested the prototype with a 40-question evaluation set and used batch APIs to reduce offline processing costs. The evaluation set helps identify issues; its size is not an accuracy score.

Offline processing
~50%

Lower API processing cost with batch APIs

To lower the cost of preparing the episode collection, I moved offline processing to batch APIs. This reduced API processing costs by approximately 50% while keeping batch work separate from interactive questions.

Evaluation
40

Questions in a repeatable evaluation set

The set includes reference answers, scoring criteria, and checks of expected behavior. Saved inputs and outputs, reusable evaluation results, and replayable failures help make comparisons repeatable.

A retrieved passage is evidence of what a speaker said—not independent verification that the statement is true. Answers can be inaccurate, and source references still need human review.
